# Using Nitrous.IO with Vagrant

## Overview

If you already have an existing development environment setup with Vagrant, you can easily move it to use Nitrous.IO as a back-end. There are several advantages in moving your development environment to Nitrous.IO.
You will have access to your Development Environment from any machine, anywhere. Also, Nitrous.IO makes collaboration with your teammates incredibly simple.

There's also a built-in snapshotting feature you can use to replicate or rollback environments.

## Prerequisites

* You will need to signup for a Nitrous.IO Pro account. Note that "Nitrous Pro" is a different website and product than (www.nitrous.io)

**Nitrous.IO Pro is currently in private beta. Please email hello at nitrous dot io to request access.**

* Install the Nitrous.IO plugin for Vagrant.

{% highlight bash %}
$ vagrant plugin install vagrant-nitrousio
{% endhighlight %}

## Configure

* You will need to create a host in [Nitrous.IO](https://pro.nitrous.io). Write down the host's `slug`.

<screenshot with hostslug highlighted>
![Host screen with slug highlighted]({{site.baseurl}}/images/articles/host-screen-with-slug.png)

* Add the Nitrous.IO specific provider configuration to your Vagrantfile.

{% highlight ruby %}
Vagrant.configure("2") do |config|
  config.vm.hostname = 'test-box'

  config.vm.provider :nitrousio do |provider, override|
    override.vm.box = 'nitrousio'
    override.vm.box_url = 'https://github.com/nitrous-io/vagrant-nitrousio/raw/master/nitrousio.box'

    provider.host = "HOST_SLUG" # copy the host slug from Nitrous.IO web app
    provider.username = ENV['NITROUS_USERNAME']
    provider.password = ENV['NITROUS_PASSWORD']
    provider.ssh_private_key_path = "~/.ssh/id_rsa"

    override.ssh.username = 'action'
  end
end
{% endhighlight %}

## Spin-up a Container

Once you have configured the Vagrantfile, you can create a new container for your project by running:

{% highlight bash %}
$ vagrant up --provider=nitrousio
{% endhighlight %}

Nitrous.IO also supports the default Vagrant provisioners (Shell, Chef and Puppet). So your existing provision scripts should work with minimal changes.

It's recommended that you don't hardcode your username and password in your Vagrantfile. Instead, provide them as environment variables when executing Vagrant commands.

{% highlight bash %}
$ NITROUS_USERNAME=foo NITROUS_PASSWORD=bar vagrant up --provider=nitrousio
{% endhighlight %}

## Lifecycle

**vagrant ssh**

Logs you into the container and allows you to poke around.

**vagrant provision**

If you make any changes to your environment, you can re-run provisioners to update the container.
It will also rsync any specified `config.vm.synced_folder`.

**vagrant halt**

Stops the container.

**vagrant destroy**

Terminates and destroys the container. (This action is irreversible)

## Syncing Folders

Currently, the plugin supports one-way folder syncing with `vagrant rsync` and `vagrant rsync-auto` (refer [Vagrant's documentation](http://docs.vagrantup.com/v2/cli/rsync-auto.html) for more details).
